## 一、门禁口径（先读这一节，避免判错）

1. **Console 零红错的口径是「排除 G6 已知项后零红错」。** G6 = 每次文档加载后**首次**进入「设置」tab 时，`rules_check_update` 打印 2 条 `http://ipc.localhost/rules_check_update` `ERR_CONNECTION_REFUSED`（source=network）+ 2 条 Tauri「IPC custom protocol failed, will use postMessage」warning。**这 6 条（2 error + 4 warning）按已知项豁免**，同文档内再次进入设置页不再复现；除此之外任何红色 error 均判不通过。
2. **「数据为空」不等于「功能失效」。** 判定 G3 / G8 之前，必须先确认观察对象是**本次变更之后**产生的数据（看「移入时间」是否晚于安装时间）。历史上已经踩过两次：2026-10-27 首验把「78 条历史行全 `—`」误判为 G3 修复失败。
3. **必须造数据再验。** G2 需要 >100 条（含小文件）、G3 需要新删文件、G5 需要「先扫描后手动删掉文件」，缺数据就判「不适用」= 判不通过。
4. 每一条都要填 **NSIS 结果** 与 **MSI 结果** 两列，只跑一种安装包视为未完成。
5. 失败项登记格式：`编号 / 现象 / 复现步骤 / 截图或 Console 片段 / 归属（回归 or 预存在）`。

## 二、证据采集

- 截图命名：`r3-<安装包类型>-<编号>-<序号>.png`（如 `r3-nsis-C05-1.png`），统一放 `docs/test-reports/evidence-r3/`。
- Console：沿用前两轮方法（WebView2 CDP 抓 `page` + `consoleAPICalled`）；CDP 不可用时退回「手动打开 DevTools 截图」，并在证据列注明降级方式。
- 每次安装都要记录：安装包完整路径、安装目录、安装耗时、退出码、`%APPDATA%\com.and0114.cclean` 是否存在及创建时间。
