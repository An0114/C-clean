# 安全策略

> 适用产品：C-Disk Cleaner（Windows 桌面清理工具）
> 仓库：<https://github.com/An0114/C-clean>
> 本文同时说明**杀软 / SmartScreen 误报**的成因与处理方式，以及**漏洞披露流程**。

---

## 1. 支持版本

| 版本 | 安全更新 |
|---|---|
| 0.6.x（当前开发线） | ✅ 接收并处理 |
| ≤ 0.5.x | ❌ 仅建议升级到最新版 |

安全修复优先进入最新发布版；旧版本不单独回补。

## 2. 产品安全模型

清理工具天然具备「批量删除文件」的能力，因此本项目的安全边界不靠提示语，而靠代码结构：

- **L0–L3 风险分级**：L3 为硬编码红线（系统目录、用户文档、浏览器敏感文件等），UI 不提供勾选，后端在执行前独立复核一次；自定义规则只允许 L1 / L2，无法覆盖 L3。
- **dry-run 预演**：执行前展示将被删除的完整清单；CLI 默认只预览不动文件。
- **保险箱**：所有删除先移入保险箱（默认 7 天可恢复），恢复失败不会破坏原文件。
- **最小权限**：主进程以普通用户权限运行；仅需要管理员权限的操作交给独立提权程序 `cclean-elevation.exe`，按需 UAC、完成即退出。该程序只接受白名单内的固定命令，参数由主进程硬编码，外部无法注入额外参数。
- **不可逆操作前留退路**：L2 清理与 WinSxS 清理前自动创建系统还原点，建点失败默认中止；删除注册表启动项前自动导出 `.reg` 备份。
- **规则库校验**：远端规则库下载后校验 SHA-256，校验失败自动使用本地版本，支持回滚到上一版。

### 网络行为

| 请求 | 目的 | 失败影响 |
|---|---|---|
| GitHub Releases `latest.json` | 检查应用更新 | 仅提示检查失败，不影响使用 |
| 规则库 JSON + checksum | 规则热更新 | 自动降级使用内置规则 |

除此之外**没有**遥测、云上传、广告 SDK、账号体系或后台常驻服务。所有扫描结果与审计数据只写入本机 SQLite。

## 3. 杀软 / SmartScreen 误报说明

### 3.1 为什么会被拦截

安装包**未做代码签名**（原因与后续计划见 [`research/code-signing-evaluation.md`](research/code-signing-evaluation.md)），因此首次运行会触发 SmartScreen「未知发布者」。此外，清理工具的行为模式与恶意软件存在重叠，启发式引擎可能因此告警：

- 批量移动 / 删除大量文件（保险箱通过同盘 `rename` 或跨盘 `copy + remove` 实现）；
- 读取并写入注册表（启动项备份、右键菜单、软件感知）；
- 按需申请管理员权限（独立提权程序）；
- 遍历用户目录与浏览器缓存目录（只读扫描，不读取文件内容）。

以上行为都由产品功能决定，代码、规则库与构建脚本全部开源，可逐行审计。

### 3.2 如何自行验证

1. 从本仓库源码自行构建对比；安装包只从 GitHub Releases 下载，不使用第三方转载；
2. 用 Process Monitor 观察进程行为：扫描阶段只有读操作；删除阶段文件进入 `safe_box`，不会直接抹除；
3. 断网运行：除更新检查与规则库更新外没有其他外联；
4. 审计日志（`audit_log` 表）记录每次扫描 / 清理 / 恢复 / 永久删除的来源与结果。

### 3.3 被误报时怎么办

- **不要**把整个磁盘或 `C:\` 加入杀软排除列表；
- 如确需排除，只排除安装目录（例如 `%ProgramFiles%\C-DiskCleaner`）与便携版所在目录；
- 欢迎在 [Issues](https://github.com/An0114/C-clean/issues) 提交误报信息：杀软名称与版本、病毒库版本、报毒名称、安装包版本与 SHA-256、触发操作。我们会把样本提交给厂商申诉；
- 请不要在公开 Issue 中粘贴完整磁盘路径、用户名等个人信息。

## 4. 安全披露流程

### 4.1 报告渠道

**首选** GitHub 私密安全公告：[提交安全公告](https://github.com/An0114/C-clean/security/advisories/new)。

如果无法使用该通道，请先开一个不含漏洞细节的 Issue，说明「需要私密渠道」，维护者会回复进一步联系方式。**请勿在公开 Issue / PR / 讨论区披露可直接利用的细节。**

### 4.2 报告内容

- 受影响版本与操作系统版本；
- 复现步骤（最小化、可重复）；
- 影响描述（例如：可删除白名单外文件、可绕过 L3、提权参数可注入）；
- 如已有 PoC，请说明触发条件与预期 / 实际结果；
- 是否已公开披露的计划。

### 4.3 响应时限（目标值）

| 阶段 | 目标 |
|---|---|
| 确认收到 | 7 天内 |
| 初步评估（是否成立、影响范围） | 14 天内 |
| 修复或缓解方案 | 30 天内（严重问题优先） |
| 协调披露 | 修复发布后 90 天内，或与报告者另行约定 |

若 7 天内未收到确认，请在同一公告中补充提醒。

### 4.4 处理原则

- 修复发布前不公开细节；
- 修复版本在 CHANGELOG 中说明影响范围，但不提供可直接利用的 PoC；
- 经报告者同意后在致谢中署名，也可选择匿名。

### 4.5 范围

**受理**：

- 绕过 L3 红线或内置白名单，导致可删除受保护路径；
- 路径规范化 / 符号链接 / 8.3 短名绕过，导致删除白名单外文件；
- 保险箱逃逸、恢复路径穿越；
- 提权程序参数注入或命令白名单绕过；
- 规则库校验绕过导致执行任意规则；
- 其他可导致数据丢失、权限提升或远程代码执行的问题。

**不受理**：

- 「安装包未签名 / SmartScreen 提示」本身（已知并已在本文说明）；
- 需要先获得管理员权限或物理访问才能成立的本地问题；
- 第三方依赖的已知漏洞，但没有可利用路径；
- 社会工程、钓鱼、拒绝服务（例如扫描耗时）等非代码缺陷。
