# v0.1.6 升级闭环验证手册

> **执行者：用户本人，在 v0.1.6 正式发布之后手动执行。DevAgent / 测试 Agent 不执行本手册。**
> 目的：验证 updater 端到端闭环——装旧版 → 检查到新版本 → 下载安装 → 重启 → 确认已在新区间。这条链路此前**从未真机跑通**（task-048 只验证了「banner 能弹出」，没做「点更新 → 装完重启」）。
> 预计耗时：15–25 分钟（含一次安装、一次下载安装、一次重启）。

## 零、前置条件（缺一不可）

| # | 条件 | 怎么确认 |
|---|---|---|
| P1 | **v0.1.6 已发布到 GitHub Releases** | 打开 `https://github.com/An0114/C-clean/releases`，能看到 `v0.1.6` 且资产含 `.exe` / `.msi` / `.exe.sig` / `latest.json` |
| P2 | **`latest.json` 的 version 是 0.1.6，URL 指向 v0.1.6** | 直接打开 `https://github.com/An0114/C-clean/releases/latest/download/latest.json`，看 `version` 与 `platforms.windows-x86_64.url` |
| P3 | **v0.1.5 安装包仍在** | Releases 页有 `v0.1.5`，下载 `C-DiskCleaner_0.1.5_x64-setup.exe` 备用 |
| P4 | 签名配对 | v0.1.6 的 `.exe.sig` 存在；`tauri.conf.json` 的 `plugins.updater.pubkey` 与发版私钥配对（task-035 已证实 keyid `52ACA0C8DAA19EB3`） |
| P5 | 干净环境 | 建议在**非开发机**或至少卸载现有版本 + 清空 `%APPDATA%\com.and0114.cclean` 后开始，避免残留 DB 干扰 |

> **顺序不能反**：必须**先发 v0.1.6，再装 v0.1.5**。反过来装完 v0.1.5 时若 v0.1.6 还不存在，检查更新只会返回「已是最新」，闭环验不了。

## 一、步骤 1：干净目录安装 v0.1.5

1. 卸载机器上现有的 C-Disk Cleaner（设置 → 应用 → 卸载）。
2. 删除数据目录：`%APPDATA%\com.and0114.cclean`（确认没有要保留的保险箱文件后再删）。
3. 在**非系统盘**建一个干净目录，例如 `D:\verify\v015\`。
4. 用 NSIS 包静默/交互安装到该目录：
   ```powershell
   .\C-DiskCleaner_0.1.5_x64-setup.exe
   ```
   若 NSIS 因 `perMachine` 弹 UAC 且当前不是管理员，改用 MSI per-user：
   ```powershell
   msiexec /i "C-DiskCleaner_0.1.5_x64.msi" /qn ALLUSERS=2 MSIINSTALLPERUSER=1 INSTALLDIR="D:\verify\v015"
   ```
5. **记录基线**（后面步骤 4 要对比）：
   - 安装目录路径：`________________`
   - 安装目录文件清单（`Get-ChildItem -Recurse -File | Select FullName` 存一份）
   - `%APPDATA%\com.and0114.cclean` 是否已生成

**通过标准**：安装退出码 0；安装目录有 `C-DiskCleaner.exe`；`rules\`、`scripts\` 子目录齐全。

## 二、步骤 2：启动 v0.1.5，确认「发现新版本」

1. 从安装目录启动 `C-DiskCleaner.exe`。
2. 等 3–10 秒（启动时自动 `check()`，非阻塞）。
3. 观察顶部：应出现**蓝色非阻塞 banner**「发现新版本 v0.1.6」，带「立即更新 / 稍后」两个按钮。
4. 点「稍后」，确认 banner 消失但**主界面可正常操作**（这是「非阻塞」的含义）。
5. 进「设置」tab → 应用更新卡片，应同样显示「发现新版本 0.1.6」。

**通过标准**：banner 与设置页卡片显示的版本号一致，且都是 `0.1.6`。

**失败排查**：banner 不出现 → 先看 `latest.json` 是否可达（P2）；再确认本机时间是否正确（签名/证书时间校验）；再看 Console 是否有 updater 相关红错。

## 三、步骤 3：点「立即更新」→ 下载 → 安装

1. 回到 banner 或设置页，点「立即更新」。
2. 观察是否出现下载进度反馈。
   - **已知**：v0.1.6 **没有**下载进度条（M3 才做）。若界面在下载期间「看起来没反应」属预期，不是缺陷。
3. 下载完成后应用会自动退出并启动安装程序（或提示重启）。
4. 若弹出 UAC，允许。
5. 等待安装完成。

**通过标准**：安装程序确实被拉起、安装完成；**若失败，记录卡在哪一步**（下载失败 / 签名校验失败 / 安装程序未启动）——这三种失败原因不同，排查方向完全不同。

> 若本次卡在「签名校验失败」，检查发版私钥与 `pubkey` 是否配对（P4），并回看 release run 日志里 `.sig` 是否成功产出。

## 四、步骤 4：重启并确认已在 v0.1.6

> **与任务书原文的偏差**：任务书要求「重启后『关于』页显示 v0.1.6」，但本应用**当前没有「关于」页**，设置页也不显示当前版本号（只显示远端可更新版本）。因此改用以下三条等效验证，**任两条命中即视为通过**：

| 方式 | 操作 | 期望 |
|---|---|---|
| A. 安装包/安装记录版本 | 设置 → 应用 → 已安装的应用 → C-Disk Cleaner | 版本显示 `0.1.6` |
| B. 可执行文件属性 | 右键安装目录 `C-DiskCleaner.exe` → 属性 → 详细信息 | 「产品版本」= `0.1.6` |
| C. 安装目录对比 | 与步骤 1 记录的基线对比 | 安装目录路径未变（覆盖安装）；文件时间戳更新 |

**通过标准**：A 或 B 至少一条显示 `0.1.6`，且应用能正常启动（不是装完打不开）。

## 五、步骤 5：基本功能回归（5 分钟）

装到新版后逐项点一遍，确认升级没打坏主链路：

| # | 操作 | 期望 |
|---|---|---|
| R1 | 仪表盘 → 开始扫描 | 进度条推进到 **100% 满格**（v0.1.6 修的 G7） |
| R2 | 清理页 | 有分页栏；总数与扫描计数一致（G2） |
| R3 | 选 1–2 项 → 清理已选 | 结果条正常；释放字节数合理（G5） |
| R4 | 保险箱页 | 新行「来源」列显示 `#N`；老行显示「历史（无来源）」（G3 / G8） |
| R5 | 仪表盘「清理轮次」 | 数值 +1（不是 0）（G4） |
| R6 | 设置页 | 规则库卡片正常，「检查更新」不再显示有新版本（已是最新） |

**通过标准**：6 条全过；任何一条不通过，记录现象并回写 `docs/PROJECT_STATE.md`「已知问题」。

## 附：常见卡点速查

| 现象 | 最可能原因 | 先看哪 |
|---|---|---|
| 不弹 banner | `latest.json` 不可达 / version 未递增 | P2 里直接打开 latest.json |
| 弹了但点更新报签名错误 | 私钥与 `pubkey` 不配对 | release run 日志 + P4 |
| 下载完没反应 | 安装器未拉起（权限/杀软拦截） | Windows 事件查看器 + 杀软日志 |
| 装完还是旧版本 | 装到了别的目录（覆盖失败） | 步骤 4 方式 C 对比安装路径 |
| 装完打不开 | 资源缺失（`rules/` `scripts/` 未落位） | 安装目录检查 `rules\`、`scripts\`，有无 `_up_` |
