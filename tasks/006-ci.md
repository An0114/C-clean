## 需求 & 验收标准

> 每条都可机器复核。DevAgent 自验时逐条勾选，任一不过不得 push。

### A. `rust-toolchain.toml`（仓库根新建）

1. 文件内容（DevAgent 可微调 channel 具体小版本，但必须满足以下约束）：
   ```toml
   [toolchain]
   channel = "1.77.0"   # 或当时最新 stable；在实现备注里写明选定版本与理由
   components = ["rustfmt", "clippy"]
   targets = []          # 本任务不钉 target；x64/ARM64 出包留发布任务
   profile = "minimal"
   ```
2. 本地执行 `rustup show active-toolchain` 必须读出 channel 版本（证明 toolchain 文件生效）；
3. 该文件与 `Cargo.lock` 一起入库（决策 #2：Cargo.lock 入库）。

### B. `.github/workflows/ci.yml`（新建）

4. 工作流触发条件：
   - `push` 到 `main`；
   - 所有 `pull_request`（任何分支）。
5. Runner 固定为 `windows-latest`（**不**跑 `ubuntu-latest` / `macos-latest` 矩阵）。
6. Job 至少包含以下 steps（顺序不得调换）：
   - **Step 1: Checkout**：`actions/checkout@v4`（默认即可，`fetch-depth: 1`）；
   - **Step 2: 安装 Node + pnpm**：`actions/setup-node@v4` 钉 `node-version: 20`；然后用 `corepack enable && corepack prepare pnpm@9 --activate` 激活 pnpm 9（不另装 pnpm action）；
   - **Step 3: 安装 Rust**：`dtolnay/rust-toolchain@stable`（会自动读取 `rust-toolchain.toml`），并在其后接 `Swatinem/rust-cache@v2` 缓存 cargo 构建产物；
   - **Step 4: 格式检查**：`cargo fmt --all -- --check`，任何 diff 直接 fail；
   - **Step 5: Clippy**：`cargo clippy --workspace --all-targets -- -D warnings`，任何 warning 直接 fail；
   - **Step 6: Rust 测试**：`cargo test --workspace`，失败即 fail；
   - **Step 7: 前端安装**：`pnpm install --frozen-lockfile`（在仓库根跑；若 lockfile 在 `app/` 下则 cd 进去）——**必须** `--frozen-lockfile`，lockfile 漂移直接 fail；
   - **Step 8: 前端构建**：`pnpm --filter app build`，失败即 fail；
   - **Step 9: 规则库 SHA-256 校验**：用 PowerShell（runner 是 Windows）算 `rules/cache_rules.json` 的 SHA-256，与 `rules/rules_meta.json` 里的 `checksum_sha256` 字段比对，不一致直接 fail；
   - **Step 10: 规则库 JSON 合法性**：用 `cargo test -p engine`（Step 6 已跑）间接覆盖——但额外加一步用 PowerShell `Get-Content | ConvertFrom-Json` 验证两个 JSON 文件能被解析。
7. 工作流 YAML 必须通过 `actionlint` 或 GitHub Actions 编辑器无语法错误（DevAgent 本地装不了 actionlint 也无所谓，只要 push 后 Actions 不报错即可）。
8. **不**配置 `on: [release]` / `on: [workflow_dispatch]` 出包步骤；
9. **不**配置缓存 `node_modules`（cargo 缓存用 rust-cache 即可，前端缓存本任务不做）；
10. **不**配 `env` 里的 secrets（本任务不需要任何密钥）。

### C. 前端 lint/test 占位

11. 检查 `app/package.json` 是否已有 `lint` 与 `test` 脚本：
    - 若**已有**且命令真实可用（如 ESLint / Vitest），在 CI 里追加 `pnpm --filter app lint` 与 `pnpm --filter app test` 两个 step；
    - 若**没有**（task-001 只搭了 Vite+React 骨架，大概率没有），在 `app/package.json` 里补两个占位脚本：
      ```json
      "lint": "echo \"TODO(ui): 待前端组件落地后接入 ESLint\"",
      "test": "echo \"TODO(ui): 待前端组件落地后接入 Vitest\""
      ```
      并在 CI 里**不**跑这两个命令（避免误导），等后续 UI 任务再启用。
12. 无论走哪条路径，DevAgent 必须在实现备注里说明 `app/package.json` 改动与否、CI 里是否加了 lint/test step。

### D. 规则库 SHA-256 校验步骤（Step 9）

13. 校验脚本（PowerShell，约 10 行）逻辑：
    - `$hash = (Get-FileHash rules/cache_rules.json -Algorithm SHA256).Hash.ToLower()`；
    - `$meta = Get-Content rules/rules_meta.json -Raw | ConvertFrom-Json`；
    - 若 `$hash -ne $meta.checksum_sha256` → `Write-Error "checksum mismatch: expected $($meta.checksum_sha256), got $hash"` 并 `exit 1`；
    - 若一致 → `Write-Host "rules checksum OK: $hash"` 并 `exit 0`。
14. 该步骤与 task-005 运行时 `loader.rs` 的校验**互为冗余**：CI 在合并前挡住手改 cache_rules.json 但忘了更新 rules_meta.json 的情况；运行时在用户机器上挡住传输篡改。
