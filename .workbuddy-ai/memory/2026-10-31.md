### 环境坑（新，很值得记）

**vitest 全量跑会 EPERM 挂掉，必须把 TEMP 指到仓库内**：
```bash
TEMP="D:/GitHub/C-clean/target/vitest-tmp" TMP="D:/GitHub/C-clean/target/vitest-tmp" pnpm --filter app test
```
症状：`EPERM: operation not permitted, open 'C:/Users/An/AppData/Local/Temp/<random>/web/<hash>'`，
栈顶是 `node-brokered-fs-shim.cjs`（WorkBuddy 的 fs broker 拦截）。表现是「跑了 8-9 个文件就
中断 + 报 2-3 个 Unhandled Error」，且**不是每次都在同一个文件挂**。
之前的「`rm -rf target/vitest-tmp` 后重跑」这次不管用——那只是碰运气，真正原因是
vitest 把 web transform 缓存写到 `%TEMP%`，被 broker 拒。**以后一律带 TEMP/TMP 前缀跑前端测试。**

### 技术要点

- **DFS → BFS 是本任务最大的收获**。带「时间/条目预算」的目录遍历，DFS 会在预算用尽时
  扎进某个深层子树，浅层目录一个都没扫到。本机实测同一份 20 秒预算：
  DFS 扫 16 万条目出 21 条 Top → BFS 扫 20 万条目出 99 条 Top，合计 16.9 GB → 59.6 GB。
  **凡是「有预算上限的树遍历」，默认就该 BFS**，除非业务明确要求先深后浅。
- `SHQueryRecycleBinW`（shell32，`Win32_UI_Shell` feature 已开）一次拿到全盘回收站大小；
  **任务书写的 `SHGetDiskFreeSpace` 是查磁盘剩余空间的**，完全不相干。
- hiberfil.sys **不要 `File::open`**（内核持有必失败），`fs::metadata().len()` 就够。
- 单测里 `scan_recycle_bin` **不能断言大小**：API 查的是整盘回收站，临时目录也会解析到
  同一个盘，所以每台机器数字都不同（本次 1593943 B）。只断言结构，大小断言改成
  「total == 各分类之和 + Top 之和」这种**不变量**。
- `#[ignore]` 的真机冒烟用例（`--ignored --nocapture real_scan`）是在 WebView2 起不来的
  机器上拿「真实数据证据」的好办法——比截图弱，但比纯 mock 强得多，而且可复现。

## task-067 M1 D 模块残留增强（开发轮完成，状态 testing，分支 `feature/task-067-residual-scan`，已 push）

**6 个 commit**：`d50ad0e` 后端扫描 / `4f02d39` IPC / `76f17a2` Residual 页 / `59b56b1` App tab / `8f201ab` docs(state) / `434c23c` docs(task)。门禁：cargo test **405 passed**（+23）、vitest **135**（+12）、build 220.75 kB、`tauri build` NSIS 4.41 MiB + MSI 6.51 MiB。

### 最大的教训：**「残留」这类功能的误报只能靠真机量，单测量不出来**

初版把 `%LOCALAPPDATA%`/`%APPDATA%` 当安装目录扫 → 本机 **182 条**，`AppData\Local\Huawei`、
`Roaming\LarkShell`、`Roaming\Tencent`、`Roaming\JetBrains` 全被报成残留。
根因：**AppData 是「应用数据」目录，不是「程序安装」目录，本来就不写卸载项**。
改成只扫 Program Files + 13 个系统组件黑名单 → **11 条**，耗时 **10.4s → 75ms**。

> 规律：凡是「A 里找不到 B 就判定为异常」的启发式，**假阳性一定远高于直觉**。
> 落地前必须真机跑一遍数数量级，不然做出来的东西用户看一眼就再也不打开了。

### 技术要点

- **注册表读取零新依赖**：`windows` crate 的 `Win32_System_Registry` feature 在 task-062
  就为 `SHELLEXECUTEINFOW` 的 `hkeyClass` 字段开好了，直接手写
  `RegOpenKeyExW`/`RegEnumKeyExW`/`RegGetValueW` 即可，`Cargo.toml` 一行没动。
  签名坑：`RegEnumKeyExW` 的第 5 参是 `Option<*const u32>`、第 6 参是 `PWSTR`（不是 Option），
  第 7/8 参是 `Option<*mut _>` —— 混着来，只能编译试。
- **必须读三处**：HKLM 64 位 + `HKLM\Software\WOW6432Node\...`（32 位程序）+ HKCU。
  只读 64 位会漏掉所有 32 位程序。
- **过滤三类非程序项**：`DisplayName` 空、`SystemComponent==1`、`ParentKeyName` 存在。
  不过滤会把几百条补丁/运行库列进来。
- **`SafeBoxDeleter::delete_dir` 原是 `Err` 桩**（task-016 只做文件）。实现成转调
  `delete_file` 就行——对目录而言 `fs::rename` 本来就是整体移动，结构完整保留。
- **`delete_file` 用 `metadata().len()` 算目录体积得 0** → 保险箱配额完全失效。
  这是个一直存在但从没被触发的缺陷（因为以前只删文件），本任务才踩到。
- **`delete_dir` 对不存在的路径返回 `Ok(())`（幂等）**，直接信它会记成「已移入」的假成功。
  调用前必须自己 `Path::exists()` 挡一道。

### 环境坑补充

- `reg.exe` 被沙箱安全策略拦截（Program Blacklist），**不能用来调试注册表**，
  也别想着换 shell 绕过。要查注册表就写 Rust 探针。
- vitest 的 EPERM 抖动**即使把 TEMP 指到 `target/vitest-tmp` 也会偶发**（broker 对
  仓库内路径同样拦）。表现是「跑了 11/12 个文件就中断 + 1 个 Unhandled Error」，
  重跑一次通常就过。**判断标准：`Test Files` 数量对不对，不要只看 Tests 数。**

## task-068 M1 F 模块注册表健康中心（开发轮完成，状态 testing，M1 收官，分支 `feature/task-068-registry-health`，已 push）

**6 个 commit**：`16a4ec4` 后端扫描 / `117b050` IPC / `345ab88` 页面 / `fb95b37` App tab / `2b2de78` docs(state) / `7117e6c` docs(task)。门禁：cargo test **431 passed**（+26）、vitest **148**（+13）、build 230.32 kB、`tauri build` NSIS 4.45 MiB + MSI 6.55 MiB。

### 技术要点

- **注册表封装抽成 `scan/winreg.rs`**（task-067 塞在 residual.rs 里的那份），新增 `RegEnumValueW` / `RegDeleteKeyValueW`。公开 API 只暴露 `RegRoot` 枚举不暴露 `HKEY`，调用方不用 `use windows::...`。
- **`RegEnumValueW` 签名坑**：第 5 参 `Option<*const u32>`、第 6 参 **`Option<*mut u32>`**（不是 `*mut REG_VALUE_TYPE`）、第 7/8 参 `Option<*mut _>`。混着来，只能编译试错。
- **`RegCreateKeyExW` 被 gate 在 `Win32_Security`**（因为有 `SECURITY_ATTRIBUTES` 参数），用 `RegCreateKeyW` 可绕过——测试里建键就用它。
- **`.reg` 导出自己生成，不调 `reg export`**。除了「不 spawn 外部 exe」的原则，还有个现实原因：**`reg.exe` 会被安全软件/组策略/沙箱直接拦掉**（本机开发沙箱就拦了）。自己拼字符串还能单测。
- **计划任务读 `System32\Tasks` 的 XML**，不调 schtasks（本地化文本解析必挂，同 DISM 的坑）。但**普通用户对该目录 Permission denied**，所以加了 `taskScanAvailable` 字段区分「没有任务」和「读不到」——这个字段是必须的，不加就是骗用户。
- **只删 Run 值不删键**（`RegDeleteKeyValueW` 而非 `RegDeleteTreeW`）：删键会连带干掉同键下其他程序的启动项。
- **fail-closed + 后端独立复核 L3**：备份写不出来就不删；删除前重新读值重新判等级，不信前端传的 `riskLevel`。

### 真机抓到的 bug

Run 值里有 `%windir%\system32\SecurityHealthSystray.exe` 这种写法，**不展开环境变量 → `Path::exists()` 恒 false → 把正常程序误判成「文件已不存在」**。
修法：`extract_exe_path(&cmd).map(|p| residual::expand_env(&p))` 再判存在性（扫描和删除两处都要改，否则判风险不一致）。

> 规律：**凡是从注册表/配置里读出来的路径，判存在性前一律先展开环境变量**。这类数据里的 `%windir%` / `%ProgramFiles%` 比想象中常见。

### 真机数据质量（16 个启动项）

L3 三条全对：`SecurityHealth`（安全软件）、`RtkAudUService`（`C:/WINDOWS` 下）、`Sysdiag`（火绒）。
`exists=false` 三条都是真残留：游戏卸载后的 `nrc_launcher`、夸克/浏览器旧版更新器。

### 删除链路的测试写法（值得复用）

不想污染用户注册表，又必须真验「备份+删除」：
在 `HKCU\Software\C-Clean-Test-<pid>-<suffix>` 下造值 → 测 → 删键。
**每个用例必须用不同 suffix**：Windows 删键是延迟生效的，刚删的键处于「已标记删除」状态，同名 `RegCreateKeyW` 会返回 `ERROR_KEY_DELETED(1018)`。
