## task-058 M4 收尾（开发轮完成）

分支 `feature/task-058-m4-finishup`，8 个提交，已 push。

**4 个单元**：RmRestart 白名单、safe_box 原子性、代码签名评估、CHANGELOG v0.1.7 草稿。

**最重要的一条：任务书要的「只重启白名单内的进程」在 Restart Manager 下做不到。**
`RmRestart(hSession, dwRestartFlags, pfnProgress)` **没有按 pid 的参数**——一次调用重启本会话内**所有** `bRestartable` 进程。task-057 测试轮已经踩过相关坑（旧实现误把 pid 当 flags 传）。
所以改成 **fail-closed**：空白名单=不限制（保持现状）；非空白名单=只有被关闭的可重启进程**全部**命中才调 `RmRestart`，有一个不在名单内就整批跳过。UI 文案如实写这个语义，不能让用户以为是「只重启名单内的」。
替代方案（自己 CreateProcess 逐个重启）能做到「只重启名单内」，但会丢掉 RM 的「恢复原始命令行/工作目录」能力，代价更大。

**踩到的坑（第一版写错，已修）**：`image_file_name(pid)` 必须放在 `session.shutdown()?` **之前**。进程被杀后 `OpenProcess` 必失败 → 返回 None → 白名单拿空串 → 永远不命中 → 自动重启静默失效，而且日志看不出异常。修法是把「要重启谁」的 `restart_plan` 整体提到 shutdown 前算好。

**白名单匹配必须用映像名不用 `app_name`**：后者是 RM 的 `strAppName`（本地化 FileDescription，中文系统下 `notepad.exe` 显示为「记事本」）。task-049b 的护栏已经因此改成 `QueryFullProcessImageNameW`，白名单沿用。

**safe_box 原子性的关键洞察：不用"回滚文件"，只要把 INSERT 提到 rename 之前。**
顺序一反，INSERT 失败时文件还没动（天然无孤儿），rename 失败时 `Transaction` 的 Drop 自动 rollback 行。任务书设想的「rename 失败再把文件移回」是多余的——rename 失败本身不移动文件。
测试用**外键约束**制造 INSERT 失败（`source_task_id` 指向不存在的 `cleanup_task`），不需要 mock、不需要改 schema，断言四件事：源文件在、内容不变、box 零孤儿、DB 零行。

**代码签名评估结论「当前不做」，理由不是价格**：
- CA/B Forum 自 **2023-06** 起强制「代码签名私钥必须硬件存储」（USB token / HSM）→ **GitHub Actions runner 读不到你插在家里的 token** → 要么把全自动发版降级成手动插 token 签名，要么再买云签名服务。这条比证书价格重要得多。
- EV/OV 都需**企业实体**，本项目是个人项目。
- Azure Artifact Signing（原 Trusted Signing，~€102/年、CI 友好）**个人开发者仅限美/加**，其它地区需组织实体（待向 MS 确认中国区）。
- 给了三个「该做」触发条件：下载量达数百/月、出现企业客户、要上 winget/Store。不是简单说「以后再说」。

门禁：check/clippy/fmt 0、`cargo test --workspace` **273 passed + 8 ignored**（+11）、vitest **89**（9 files）、build **187.46 kB**。版本号保持 0.1.6 未升（发版任务再升）。
