**3 个单元**：深色/浅色主题、清理趋势图、计划自动扫描。

**主题的实现选择**：本项目**零 .css 文件**、101 个颜色全内联。所以走「纯内联 CSS 变量」——根 div 挂 `--bg/--surface/--text/--text-muted/--border`，子元素用 `var()`。不新增文件、作用域就是根节点、组件不必知道深浅。
跟随系统用 `matchMedia + change`（改 Windows 主题不用重启）。`localStorage` 只做**首屏防闪烁**，**真值仍在 DB**（启动后 `get_prefs` 校准）。

**必须记住的白名单边界**：主题只适配了 App 外壳 / Dashboard / Settings 三页。Items（26 色）/ SafeBox（19 色）/ History（8 色）**不在白名单内**，深色下仍是浅色底。已在 UI 里如实注明「部分页面仍在适配中」。这是边界决定的，不是遗漏。

**趋势图的三个取舍**：
- **只返回有记录的日期**，缺失由前端补 0（SQLite 无 `generate_series`，后端补零要递归 CTE，可读性差）
- **按本地时区** `date(...,'unixepoch','localtime')`（用户看的是日历上的那天）
- `days` **夹到 1..=365**（传 0/负数会让 `WHERE >= now` 变成查未来、静默返回空）
- 前端**手写 SVG 柱状**不用折线：数据是离散日聚合，折线会把「没数据那天」画成斜线造成误导。

**自动扫描的关键决策**：
- **不用 schtasks**：要管理员权限、卸载后计划任务容易残留、改间隔要重建任务。用 Tauri 后台线程轮询。
- **轮询不精确定时**：用户改间隔/改系统时间/休眠唤醒都会让 `sleep(到下次)` 错位；一次轮询就是一条 SQLite 查询。
- **`last_at <= 0 → 立即到期**：用户刚开开关应该马上看到效果。
- **与手动扫描用 `try_lock` 互斥**：拿不到说明用户正在扫，本轮跳过。不能用 `lock()`（会阻塞用户操作）。
- **失败也写 `last_auto_scan_at`**：否则一直失败会每 30 分钟重试轰炸。
- **只扫描不删除**：自动删除是「用户不在场时执行不可逆操作」，与产品定位冲突。

**必须装 notification 插件**（任务书前提缺失）：`Cargo.toml` + `lib.rs` + `capabilities/default.json` + 新建 `auto_scan.rs` 全在白名单外。不自己调 WinRT Toast 是因为它要注册 AppUserModelID、**只在安装态可用**（dev 弹不出来）。

**踩到的两个测试坑**：
1. 新增 checkbox/「已关闭」文本后，老用例的 `getByRole("checkbox")` / `findByText("已关闭")` **多匹配报错**。改 `getAllByRole(...)[0]`。

- **结果回传双通道**：退出码（0/2/3/4）+ 临时 JSON。**不能用 stdout**——`ShellExecuteExW` 拉起的进程拿不到 stdout（那是 `CreateProcess` 的能力）。
- **白名单校验在任何参数解析之前**，未知命令连参数都不看。
- **`SHELLEXECUTEINFOW` 被 gate 在 `Win32_System_Registry` 后面**（结构体有 `hkeyClass` 字段）——只加 `Win32_UI_Shell` 会报「no SHELLEXECUTEINFOW」。这个坑记一下。

**打包链路（值得复用）**：
`beforeBuildCommand` = `pnpm build && node ../scripts/build-elevation.mjs`。
**注意 cwd 是 `app/` 不是 `app/src-tauri`**（`../../scripts` 会找不到）。
`tauri build` 的执行顺序是「beforeBuildCommand → cargo build → 打包」，**串行**，所以脚本里跑 cargo 不会抢 target 锁。
**验证进包的硬证据：NSIS 4.05 → 4.22 MiB（+0.17 MiB ≈ 153KB exe）。**

**还原点只对 L2 触发**：为 L1 缓存弹一次 UAC + 等几十秒建点，用户会直接关掉这个功能。

## task-064 P0 收尾：7 天 purge + 风险徽标 + 全选 L1（开发轮完成）

分支 `feature/task-064-purage-badge-l1all`，5 个提交，已 push。**P0 全部清完**。

**purge_expired 的关键决策**：

## task-065 M1 C 模块 WinSxS 清理（开发轮完成，状态 testing，分支 `feature/task-065-winsxs-cleanup`，已 push）

**5 个 commit**：`a130c08` 提权白名单+dism 模块 / `be91232` 分析命令 / `53ae5e6` 清理命令+进度转发 / `ca96659` UI / `21a800e` docs(state) / `4f875e4` docs(task) 备注。门禁：cargo test **364 passed**（+30）、vitest **113**（+9）、build 206.66 kB、`tauri build` 出 NSIS 4.36 MiB + MSI 6.44 MiB。

**踩到的坑（值得记）**：
- **DISM `/analyzecomponentstore` 没有 XML 输出**（任务书说「解析 XML」是错的），只有本地化文本；必须加 `/English` 把标签锁成英文再按 `"标签 : 值"` 解析。解析要用 `split_once(" : ")`，`split(':')` 会被值里的 `08:21:46` 切坏。
- **DISM 输出是 OEM 代码页不是 UTF-8**（控制台程序写管道），`from_utf8_lossy` 会把中文路径变 `�`。手写 `MultiByteToWideChar(CP_OEMCP)` FFI（~30 行，与既有 `SRSetRestorePointW` 风格一致），比引 encoding_rs 更符合本 crate 的零依赖设计。
- **`Command::output()` 会无限等**，DISM 会挂起（等锁）。必须自己 `try_wait` 轮询 + 到点 kill；且**必须开两个线程抽干 stdout/stderr**，否则管道 4KB 缓冲写满后子进程阻塞、主线程还在等它退出 = 死锁。
- **进度文件 tail 要按字节切行**：读到半个多字节字符时先 lossy 会插 U+FFFD 改变字节长度，游标算术全错。做法是只在「最后一个 `\n` 之前」解码。
- **`std::thread::scope` 比 `'static` 线程好用**：`on_line` 常常借用调用方局部变量（`&AppHandle`），要求 `'static` 会逼着到处 clone。
- **子模块里用父模块的 `use` 名字要写 `super::`**（`use super::decode_oem;`），Rust 2018 不做隐式父模块查找——我第一版直接写 `decode_oem(...)` 编译失败。
- **`cargo test -p elevation` 不会更新 `target/debug/cclean-elevation.exe`**（只编测试 harness）。要验真实二进制得 `cargo build -p elevation` 或直接用 `app/src-tauri/binaries/` 里那份 release 产物。

**可复现的真实链路探测**（本机拿不到 UAC 时的最佳证据）：
```bash
./app/src-tauri/binaries/cclean-elevation.exe dism_analyze --result <tmp>/r.json
# exit 4 → {"ok":false,...,"message":"DISM 退出码 740","output":"Error: 740 / Elevated permissions are required to run DISM."}
```
