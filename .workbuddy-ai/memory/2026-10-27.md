根因三重叠加，已逐段定位：

**关键认知（以后写发版类任务直接复用）**：
- **版本号是 CI 注入的，仓库基线只是本地默认值**。`release.yml` 用 `scripts/release-lib.mjs patch-conf` 按 `workflow_dispatch` 输入的 version 覆盖 `tauri.conf.json`，构建后 `verify-artifacts` 硬校验安装包文件名。所以改仓库版本号**不会**和发版机制冲突，但发版时 version 必须填 `0.1.6` 才能和 tag 对上。
- **`pnpm --filter app build` 永远不含版本号**（vite build 产物是 `dist/index-<hash>.js`）。验「产物名含版本号」只能 `tauri build` 后看 `bundle/` 目录。
- **`.gitignore` 的 `release/` 会连 `docs/release/` 一起吃掉**。要负向包含必须写 `!docs/release/` 且**放在 `release/` 之后**；Git 不允许在「父目录被排除」时重新包含内部文件，但对目录本身的否定规则可以生效。验证用 `git check-ignore -v <path>`（exit 1 = 未被忽略）。
- **本应用没有「关于」页**（只有 5 个 tab：仪表盘/清理/保险箱/历史/设置），设置页也不显示当前版本。验「装完是不是新版」只能靠：① 设置→应用→已安装的应用 ② exe 属性→详细信息→产品版本 ③ 安装目录对比。
- `tauri build` 不注入 `TAURI_SIGNING_PRIVATE_KEY` 会因「public key found but no private key」非零退出（但 bundle 已产出）。

**本轮最值得记的环境坑：vitest 的 EPERM 不是代码问题，是沙箱拦系统 Temp。**
`pnpm test` 连续三次失败（只跑到 6/5/3 个文件），报
`Error: EPERM: operation not permitted, open 'C:/Users/An/AppData/Local/Temp/<rand>/web/<hash>'`，
栈里出现 `node-brokered-fs-shim.cjs:701`（沙箱 fs 代理）。**修法**：把 `TMPDIR`/`TEMP`/`TMP` 指到工作区内再跑——

```bash
TMPDIR="D:/GitHub/C-clean/target/vitest-tmp" TEMP="D://GitHub//C-clean//target//vitest-tmp" TMP="D://GitHub//C-clean//target//vitest-tmp" pnpm --filter app test
```

→ 7 files / 54 passed 全绿。**另外别和 `cargo test --workspace` 并行跑 vitest**，IO 争抢会显著加剧（并行时失败率明显更高）。
