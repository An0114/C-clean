### 三个根因（任务书全猜偏了，值得记）

**Bug-1「WinSxS DISM 退出码 3」——不是 DISM 的问题，是提权命令名从来没进 argv。**
`run_elevated(exe, cmd, args)` 里 `cmd` 只用来做白名单校验，**拼命令行时压根没用**：
```rust
all_args.push(("--result", result_str));
let args_string = build_args_string(&all_args);  // ← cmd 没进去
```
提权 exe 收到 `argv[1] = "--result"` → 白名单不认 → `EXIT_UNKNOWN_CMD(3)` 退出且**不写结果 JSON** → 主进程只看到「退出码 3 + 空输出」。

> **识别技巧**：退出码 3 正好等于提权 exe 的 `EXIT_UNKNOWN_CMD` 常量。**凡是「提权后才有反应」的功能报出小整数退出码（2/3/4），先怀疑是不是自家 exe 的约定值，别一头扎进被调用的系统工具。**

> **交叉验证法**：查 `C:/Windows/Logs/DISM/dism.log`——如果 DISM 真跑过，日志里会有 `Parent process command line: ...cclean-elevation.exe dism_analyze`。没有 → DISM 压根没启动，问题一定在上游。
> （顺带：这个 log 是 **UTF-8/ANSI**，不是 UTF-16；我一开始按 UTF-16 解，得到一堆 `䑃卉偍` 这种乱码，浪费了两轮。）

**`create_restore_point` 走同一条路，也是坏的**，但被 Bug-2 掩盖了：全是 L1 → 不需要还原点 → 那条路从未被走到。**两个 bug 会互相掩护，修完一个要回头检查「另一个是不是把它盖住了」。**

**Bug-2「扫描只出 L1」——5 个 `.ps1` 把风险等级写死成字面量 `1`。**
顺带查清：`rules/cache_rules.json` 的 `modules` 段**在扫描链路上没有任何消费者**（只用于 `whitelist_deny` 与格式校验，ARCHITECTURE 里的 `grade/` 分级模块从未实现）。**风险等级的唯一来源就是脚本**——所以「补 L2 规则到规则库」对用户可见行为零影响，而改规则库要连带改 `rules_meta.json` 的 SHA-256（loader 严格比对，改错会让规则库整体加载失败 → 清理直接报内部错误）。patch 版不引入这个风险，规则库没动。

**Bug-3「永久删除失败 + 来源缺失」——两个独立问题，都出在「整目录移入保险箱」这条新路径上。**
① `purge_item`/`purge_expired`/配额 evict 三处都用 `fs::remove_file`，而 task-067 起残留扫描把**整个目录** rename 进来 → 对目录必然失败 → 前端只剩「内部错误」。
② `SafeBoxDeleter::new(..., None)` → `source_task_id` 恒 NULL → 来源列「历史（无来源）」。

> **只读查用户真实库就能定位**：`src=None` 的三条全是**目录**，`src=1` 的两条是**文件**——形状和症状一一对应，比猜快得多。**遇到「某类操作才失败」的 bug，先去真实数据里看失败样本和成功样本的差异。**

### 环境坑

- **bash heredoc 里出现「那个 Windows 命令行解释器的英文名」会被安全策略拦**（判定为「从 bash 调用它绕过检查」），整条命令拒绝执行。代码块语言标记也别写它，用 `text`。
- 但那个解释器**有专用工具通道可用**——实跑 `scan_temp.ps1` 验证 risk 分布就是用它，比在 bash 里绕路干净。
- python 三引号里写 `SoftwareDistribution\Download` 会报 `SyntaxWarning: invalid escape sequence '\D'`（内容没错，但警告难看）；写 Windows 路径用双反斜杠或 raw string。
